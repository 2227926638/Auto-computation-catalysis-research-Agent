# MVP 实施路线

## 1. MVP 目标

第一版目标不是实现完整 Co-Scientist，而是跑通一个可审计的催化创新点发现闭环：

> 输入一个催化方向，输出不少于 20 张问题卡片，并推荐 3 个可以进入纯计算可验证性判别的高优先级问题。

推荐首个示范方向：

```text
Ru-CeO2 / 氧空位 / N2 活化与 NHx 氢化
```

## 2. 阶段划分

### M0：设计和目录固定

目标：

- 固定数据模型。
- 固定评分规则。
- 固定输出目录。
- 明确 Co-Scientist 借鉴边界。

交付物：

- 当前文件夹内的设计文档。
- 配置草案。

### M1：离线文献输入版

目标：

- 支持本地 PDF/Markdown/CSV 文献导入。
- 生成文献矩阵。
- 抽取共识、争议、空白。
- 生成问题卡片。

暂不要求：

- 自动联网全文下载。
- 专利和会议材料全自动解析。
- 复杂向量库检索。

验收标准：

- 对一个方向导入 30-80 篇资料。
- 输出不少于 20 张问题卡片。
- 每张卡片至少绑定 2 条证据，证据不足的标记为 `needs_evidence`。

### M2：轻量联网元数据版

目标：

- 接入 Crossref/OpenAlex/Semantic Scholar 元数据查询。
- 对近 5 年相似论文做初步检索。
- 生成新颖性风险提示。

验收标准：

- 每个高优先级问题有近 5 年竞争论文列表。
- 明确标记 `possible_duplicate`、`needs_angle_shift`、`safe_to_continue`。

### M3：Co-Scientist-lite 迭代版

目标：

- 加入三轮迭代：
  1. 粗生成 30-50 个问题。
  2. 批判去重为 20 个卡片。
  3. 演化排序为 3-5 个推荐问题。

验收标准：

- 每个推荐问题有完整 `ReviewResult`。
- 每个被淘汰问题有淘汰理由。
- 输出 `meta_review.md`。

## 3. 运行模式

### Fast mode

用途：

- 快速头脑风暴。
- 资料少时初步探索。

特点：

- 少量文献或用户提供材料。
- 输出粗问题。
- 证据不足时明确标红。

### Evidence mode

用途：

- 正式进入毕业主线前使用。

特点：

- 强制文献证据。
- 强制 DOI/标题/年份。
- 强制近 5 年相似工作检查。

### Co-Scientist-lite mode

用途：

- 对重点方向做多轮高质量问题发现。

特点：

- 三轮生成、批判、演化。
- 输出排序和元评审。
- 为后续 Agent 提供结构化接口。

## 4. 暂不做的功能

MVP 暂不做：

- 完整异步多 Agent tournament。
- Elo 排名。
- 自动下载付费全文。
- 大规模产业情报监控。
- 自动判断最终期刊分区。
- 自动生成 DFT 输入文件。

这些功能不是不要，而是等问题卡片质量稳定后再加。

## 5. 质量控制

每次运行必须检查：

- 是否存在无来源论断。
- 是否有同义问题重复。
- 是否把必须湿实验验证的问题误判为计算可解。
- 是否只生成“提高活性”“优化性能”这种泛问题。
- 是否明确了最小可发表结果集。
- 是否为高优先级问题给出风险说明。

## 6. 第一版成功标准

对 `Ru-CeO2 / N2 活化 / NHx 氢化` 方向：

- 生成文献矩阵。
- 生成共识清单。
- 生成争议清单。
- 生成不少于 20 张问题卡片。
- 推荐不少于 3 个问题进入纯计算可验证性判别。
- 每个推荐问题包含：
  - 文献证据
  - 未解决点
  - 计算路径提示
  - 预期结果类型
  - 最小可发表结果集
  - 风险等级
  - 毕业价值预估
